04 · How it works

Five guards. Three lanes.One record per run.

Each guard is a small Node file with labelled good and bad cases. GEL's own CI fails if a guard misses a bad case or flags a good one.

guard 1
secret-scan

AWS, GitHub, Anthropic, OpenAI, Stripe live and Slack keys, and private key blocks. Skips tests, sample keys and placeholders.

guard 2
pinned-actions

Another org's action must be pinned to a commit SHA. Your org and trusted_owners may use tags.

guard 3
workflow-permissions

Every workflow job gets a token scope, never write-all, and pull_request_target never checks out the fork's code.

guard 4
dead-links

Links to files that are not in the repo. Knows doc sites without .md, Vite public/ and symlinked READMEs.

guard 5
done-without-green

The PR says "all checks pass" and a check on its last commit failed, timed out or was cancelled.

lanes
A · B · C

Picked from the changed files, never a label. Docs and tests, product code, and workflows/auth/payment/deploy where a person approves.

loop
gel-record.jsonl

Every run writes one JSON line. Promote a guard to block once the record shows it was right.

report→block one guard→block all
05 · Eval and loop

Who checks the checker?The bench, every night.

A guard is promoted only on evidence, and GEL never changes your policy by itself. It writes advice; a person edits gel.json, and that edit is lane C.

nightly
meta-eval

Every guard against its labelled cases, then the bench on the 30 pinned repos. Fails if a guard catches fewer planted defects or raises more findings on clean code than bench/baseline.json.

per guard
gel metrics

Reads your gel-record.jsonl files and your gel-labels.json: runs, fail rate, precision, first-pass share, p50 and p95 time.

flywheel
promote / demote

Promote after 20 runs, 5 labelled findings and 95% precision. Demote a blocking guard on one false alarm. Each false alarm is listed as a hard case to add to cases.json.

before release
release-gate

A shared workflow in flisk-sh/.github: waits for every check on the release commit and fails on a red or missing required one.

after deploy
deploy-health

Curls the deployed URL until it answers with the expected status and text, or fails the release.

org view
Cilytics

The org CI dashboard (flisk-sh/cilytics, for any org or user) reads the latest gel-record of each repo: which repos run GEL, findings, blocks.

06 · Limits

What GEL misses.Measured the same way.

We planted these too, so the recall above is not 100% by choice of test.

PlantedCaughtWhy
Google API key in a source file0/30Not in the rules yet.
Password inside a database URL0/30Not in the rules yet.
AWS key inside a test file0/30On purpose: test files are full of fake keys.
HTML <a href> inside a markdown file0/30Markdown files are read for markdown links only.
A write scope the job never uses0/30GEL checks that a scope is set, not that it is needed.
Org default token setting–workflow-permissions reads files only. If the org default token is read-only, a job without a permissions key is safer than GEL says.
Protection outside workflows–"Their CI today" reads workflow files only. Push protection, pre-commit hooks and branch rules are not seen, so it is a lower bound.

08 · Install

Two lines.Then it runs on every PR.

Starts in report mode. Add a gel.json when you want a guard to block.

As a step
- uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- uses: flisk-sh/gel@v1
As a job
jobs:
  gel:
    permissions: { contents: read, checks: read, pull-requests: read }
    uses: flisk-sh/gel/.github/workflows/gel.yml@v1
On your laptop
npx github:flisk-sh/gel run --root .
gel.json
{
  "mode": "report",
  "guards": { "secret-scan": "block" },
  "trusted_owners": ["your-org"]
}

Run the bench yourself: node bench/run.mjs && node bench/claims.mjs. Method: bench/README.md.
